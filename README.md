[![Docker Image](https://img.shields.io/badge/docker-locustbaby%2Ftrivy--ui%3Av0.0.5-blue?logo=docker)](https://hub.docker.com/r/locustbaby/trivy-ui)

[![Go Version](https://img.shields.io/badge/Go-1.25+-00ADD8?logo=go)](https://golang.org)
[![React Version](https://img.shields.io/badge/React-19-61DAFB?logo=react)](https://react.dev)

A modern, high-performance web dashboard for visualizing, auditing, and analyzing security scan results generated by the [Trivy Operator](https://github.com/aquasecurity/trivy-operator) across Kubernetes clusters.

---

## Key Highlights

- 🌐 **Multi-Cluster Fleet Hub**: Centralized cross-cluster security overview, global 30-day severity trends, cluster risk rankings, and directory cards.
- 🛡️ **Comprehensive Trivy Operator Support**: Automatically discovers all Trivy CRDs — Vulnerability, ConfigAudit, RBAC Assessment, Exposed Secrets, Infra Assessment, Compliance, and SBOM (including cluster-scoped variants).
- 📊 **Executive & Engineering Views**: Equal-height symmetrical layouts featuring 30-day vulnerability volume, scan breakdown matrices, and top vulnerable workloads.
- 🗂️ **Modern UX & Navigation**: Resizable sidebar (220px–480px) with persistent width, Aqua Security semantic iconography, and instant type search.
- 🔐 **Authentication & Fine-Grained RBAC**: File-backed local authentication (`auth.yaml`) with user/group scopes, browser password manager integration, and anti-timing protections.
- ⚡ **High-Performance Architecture**: Informer-based in-memory caching with disk snapshot persistence, sub-millisecond response times, and background polling sleep when tabs are inactive.

## Quick Start

### Option 1: Docker Standalone

Run Trivy UI directly with Docker by mounting a directory containing your kubeconfig file(s):

```bash
docker run -d \
  --name trivy-ui \
  -v /path/to/kubeconfigs:/kubeconfigs \
  -e KUBECONFIG_DIR=/kubeconfigs \
  -p 8080:8080 \
  locustbaby/trivy-ui:v0.0.5
```

Open `http://localhost:8080` in your browser. Every context in each mounted kubeconfig file is automatically discovered and initialized as a separate cluster.

### Option 2: Deploy with Helm (Kubernetes)

Deploy to your Kubernetes cluster directly from Docker Hub's OCI registry:

```bash
helm upgrade --install trivy-ui oci://registry-1.docker.io/locustbaby/trivy-ui
```

To provide multiple cluster credentials via a Secret:

```bash
kubectl create secret generic kubeconfigs \
  --from-file=prod=/path/to/prod-kubeconfig \
  --from-file=staging=/path/to/staging-kubeconfig

helm upgrade --install trivy-ui oci://registry-1.docker.io/locustbaby/trivy-ui \
  --set kubeconfigs.create=false \
  --set kubeconfigs.secretName=kubeconfigs
```

## Authentication & Access Control (RBAC)

Trivy UI includes built-in file-backed authentication with fine-grained role-based access control (RBAC):

- **Fine-Grained Scopes**: Restrict users or teams to specific clusters, namespaces, or cluster-scoped audit reports.
- **Native Login Experience**: Seamless integration with browser password managers (Chrome, Safari, 1Password, Bitwarden), show/hide password toggle, and "Remember username".
- **Hardened Security**: Bcrypt password hashing, in-flight concurrency limiting, and anti-timing protections.

```yaml
# auth.yaml example
version: v1
users:
  admin:
    passwordHash: "$2a$12$REPLACE_WITH_YOUR_BCRYPT_HASH"
    scopes:
      - cluster: "*"
        namespaces: ["*", "_"]  # All Namespaced and Cluster-scoped reports
  developer:
    passwordHash: "$2a$12$REPLACE_WITH_YOUR_BCRYPT_HASH"
    scopes:
      - cluster: "prod"
        namespaces: ["team-a"]   # Restricted to team-a in prod
```

### 📖 How to Configure Authentication:
- 🔐 [**Password Hashing & `auth.yaml` Syntax Guide**](docs/user-guide/02-authentication-and-access-control.md#1-generate-password-hash) — How to generate bcrypt hashes and structure user/group scopes.
- 🐳 [**Docker Standalone Setup (`-e AUTH_MODE=local`)**](docs/user-guide/02-authentication-and-access-control.md#4-run-with-docker-standalone) — Mount `auth.yaml` and pass session keys via Docker flags.
- ☸️ [**Kubernetes / Helm Setup (`--set auth.mode=local`)**](docs/user-guide/02-authentication-and-access-control.md#3-deploy-to-kubernetes-with-helm) — Deploy using Kubernetes Secrets and Helm values.

## Architecture

```
trivy-ui/
├── go-server/         # High-performance Go backend with K8s client-go informers
├── trivy-dashboard/   # Modern React 19 + TypeScript + Vite + Tailwind CSS frontend
├── charts/            # Production-ready Helm chart
└── docs/              # Comprehensive user and architectural documentation
```

### Data Flow
1. **Discovery**: Backend dynamically discovers Trivy Operator CRDs and namespaces via the Kubernetes API.
2. **Streaming Watch**: Kubernetes Informers establish persistent watches over discovered report types across all clusters.
3. **Optimized In-Memory Store**: `SetTransform` strips large unused fields, keeping memory lean and queries sub-millisecond.
4. **On-Demand Detail Fetch**: Full report payloads and CVE remediations are loaded on demand and cached with a short TTL.
5. **Snapshot Persistence**: Disk caching enables immediate warm startup on pod restarts without blocking on full cluster re-syncs.
